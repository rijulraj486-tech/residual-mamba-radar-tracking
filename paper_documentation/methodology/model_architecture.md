# Causal Residual Mamba architecture

Implementation: `src/radar_tracking/models/tracker_model.py`, `bimamba_encoder.py`, `prediction_head.py`; Stage 5B config records selected architecture. The historical class/module name `BiMambaTrackerModel`/`BiMambaEncoder` is compatibility naming. `encoder_direction` is frozen as `forward`; the encoder creates only `forward_layers`, applies Mamba to the left-to-right sequence, and has no reverse branch or fusion of future context. CUDA is required by this repository's Mamba block.

For each observation time the 21 features, in concatenation order, are: range (1), sin bearing (1), cos bearing (1), Cartesian x/y (2), Δrange (1), wrapped Δbearing (1), ΔCartesian x/y (2), coarse six-state estimate (6), and repeated initializer six-state (6). The first differences are zero at index 0. Coarse position comes from range/bearing conversion; velocity uses adjacent Cartesian positions except index 0 from initializer; acceleration uses adjacent coarse velocities except early values inherited from initializer. Shapes are `[N,21,T]`, then transposed to `[N,T,21]`.

Projection: Linear 21→128, LayerNorm(128), SiLU. Three residual blocks each perform pre-LayerNorm→Mamba(d_model=128,d_state=16,d_conv=4,expand=2)→dropout(0.08) plus residual, then LayerNorm→feed-forward Linear(128,256)→SiLU→Linear(256,128)→dropout and residual. Encoder has final LayerNorm; model applies output LayerNorm. Prediction head is Linear(128,256)→SiLU→Linear(256,128)→SiLU→Linear(128,6). It predicts a correction which is added to the coarse state sequence. M0 and M1 have 619,014 trainable parameters in selected configurations (verified in config/run records); M1 statistics are buffers/sidecar data, not trainable parameters.

Causality evidence: Stage 3 `preflight_report` records future-suffix perturbation and sequence-extension consistency checks for frozen checkpoints. This source has no bidirectional pass and no future observation input at time t by design.
